# 个性化识别 MVP（2026-11-06 设计，2026-11-07 更新）

本轮明确授权 A–F；历史“停止、不开发 AI/UI”仅描述上一阶段。现有采集器、正文开关、截图区域许可保持。截图留存与原图不落盘存在需求冲突，在策略确认前仅支持文本证据，不还原历史屏幕。

## A：检查与设计

现有模块：Engine 单调时钟与区间状态机、Windows 前台适配、独立 UIA/OCR 进程、v1 活动与 v2 content_samples、CLI 生命周期。未发现 ActivityWatch 分析专文、浏览器 URL、任务、档案、反馈或界面。未读取私人正文；数据库结构以现有 SQL 与 Repository 为依据。

新增 personalization 模块，原始活动与分析表分离。一个识别结果对应一个原始 interval；事件引用由相同 session、开始时间与 active 状态关联，不能靠时间临近猜测。多个片段可以使用同一任务标签，但不合并基础区间。保留 event_id、interval_id 外键，设备、平台、会话和时区从原始记录查询。

扩展迁移仅在首次启动个性化模块时执行；旧采集命令继续使用 v2，新 Repository 兼容 v3。迁移事务失败回滚；提供 v3→v2 回退脚本，回退会清除新增个性化数据，必须停止所有客户端后由用户明确执行。新功能不自动复制包含私人数据的备份。

档案、人工案例、确认规则、自动推断分表保存。案例仅引用原始证据，不复制正文；7 天后不能再用于文本检索。人工命名、修订随区间最多保留 90 天。用户主动填写的档案和规则视为持久配置，可删除；不自动将历史正文提升为永久规则。

层级：明确规则 → 人工案例 → 可选文本模型 → unknown。规则至少需内容条件，软件名称不能单独确定任务。冲突回退待确认。模型只能返回已提供候选 ID 与证据 ID，无工具权限，时间不进入模型输出。每次重算保留人工结果。默认不联网，发送前预览当前批次、独立确认，API Key 仅 Credential Manager。

## B–F 实施与门槛

- B：结构化档案、自然语言本地建议、确认后保存、编辑；测试确认与脱敏。
- C：区间证据适配、Provider、保守分层识别；测试无证据、错误引用、失败降级、时间不变。
- D：桌面三页、待确认队列、人工修订；测试重算不覆盖、私人化与删除。
- E：记忆复用、组合规则、反例/冲突/禁用/删除、导出；测试相似场景改善与不相关负例。
- F：合成标注评估与完整回归；真实全天采集、真实云端服务和实机交互需单独记录，不以合成结果代替。

UI 使用已验证本机 Python 3.12.13 x64 / Tk 8.6.12；无新增第三方运行依赖。数据库与识别在单工作线程执行，UI 仅展示和提交请求；采集仍使用原显式 CLI。后续可替换展示层，不重写采集。
